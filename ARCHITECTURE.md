# Architecture

One Rust binary, UI in iced (tiny-skia CPU renderer). It runs as a resident tray
app: the overlay window is created hidden at start, so a trigger only has to
capture the screen and show it.

## Modules

| Module | Role |
|---|---|
| `main.rs` | Argument parsing, single-instance hand-off, starts tray + shortcut + UI. `Trigger` = what any source asks for. |
| `hotkey/` | Global shortcuts from the config (capture + one per quick action; `global-hotkey`, or the Wayland portal) and the per-user command socket behind `opencircle capture` / `opencircle run <action>`. `hotkey::reload(&Config)` re-registers after a settings change. Wayland portal ids = `Binding::portal_id` (a non-default key rides in the id, because GNOME keeps the key it stored under an id). |
| `config.rs` | The one config reader/validator. `config::current()` is the running app's config (one source of truth: panels read it, `set_current` replaces it when Settings saves). New settings: add the field + default + check in `parse` + a round-trip test, then a row on its page in `ui/screens/settings/pages/`. `general.default_action` = what Enter runs (`actions::default_for`), `general.save_folder` = Save's start folder, `translate.live_interval_ms` = the live layer's period, `translate.source` / `target` = the languages (`auto` = detect). `[selection]` = snap / shape, search at once / wait, Lens / AI / both; `[look]` = the active look: a preset (`PRESETS`, one table of `Look`s) or `[look.custom]`; `config::look()` reads it without cloning the config (the edge every frame, the widgets on every style), so a saved change applies at once. |
| `capture/` | One frozen RGBA frame of a monitor, or of every monitor at once (snip); one file per platform (`monitors`, `grab`, `pointer`). `choose` = the monitor holding most of the active window (`window_rect::active_rect`: not the desktop, taskbar or ours), else the pointer's, else the primary: Circle to Search, translate and quick actions open there (`active_monitor`). Wayland: the portal's whole desktop, as before. `window_rect.rs`: visible windows, topmost first (snip Window mode), and the foreground window. `cursor.rs`: the pointer drawn into a snip (`snip.cursor`). `uia.rs`: a window's controls (Windows UI Automation) for snapping. `stitch.rs` + `scroll.rs`: scrolling capture (started by the editor toolbar's button; the pill window is kept out of the frames, `windows::hide_from_capture`). |
| `ocr/`, `mt/` | OCR (PP-OCRv5) and offline translation (OPUS-MT) on ONNX Runtime, only in the helper process `opencircle ocr-worker` (`ocr/worker.rs`: requests, the serve loop; models load on first use and stay). `ocr/session.rs`: the app side (framed, request ids, one request at a time, timeout -> kill -> next call respawns). `ocr::hold()` keeps ONE warm helper while held: live mode (`ui/live_layer.rs`) and an open overlay (`App::helper`) each hold one; the last drop kills it; `ocr::keep_warm()` (offline translation) holds it until 60 s unused. Unheld calls get a child per call. `ocr/system.rs`: Windows OCR (`Windows.Media.Ocr`) in the app's process, for main mode's whole screen (`ocr::route`) and for translation, one-shot and live (`pipeline::Real::recognize`, `system_reads`). The decoder's output layer is folded once at load (`session.disable_quant_qdq`), else each decoding step rebuilt it. |
| `translate/lang.rs` | The ONE language table (code, English and native name, script, RTL, OCR recognizer id): pickers, the AI prompt, RTL layout and recognizer choice read it. `ocr::models::RECOGNIZERS` = one pinned recognizer per script (en, latin, arabic, cyrillic, cjk; a source picks one, `auto` = English, then the other downloaded ones when it reads badly: `ocr::Read`); `mt::PAIRS` = one pinned OPUS-MT model per direction. New language: a row (+ a recognizer / pair entry if it has one). |
| `ui/mod.rs` | The iced daemon: overlay window state, capture on a thread, open / close (the multi-step `Hiding`), running actions, held Lens pages, `background` (thread work → messages). |
| `ui/overlay.rs` | The canvas over the frozen frame: dim, strokes, selection rules (`classify`: tap / scribble / drag / loop; `settle` = the selection and the stroke it keeps, a scribble's padded hull), corner handles (resize / move math), the Shift count badge, mouse / wheel / key events. `View` = the zoomed (1x–4x) and panned part of the frame: selections live in image px (the overlay at 1x), so crops are right at any zoom. The wheel zoom eases (`ui/app/zoom.rs`, #89): a notch sets a target, the drawn `Opening::view` moves there by the clock (`View::lerp`, `motion::GLIDE` Standard; a notch on the way retargets from where it is, the pointer's frame pixel kept under it; reduced motion = at once); while it eases or a zoomed view is panned the frame is drawn by `Zoomed` (Nearest, fractional) and the dim as whole-row rectangles, at rest by the image widget's crop with its usual filter. Timing: `frame_times::zoom_frame_times` (by hand, release). Snap (`[selection] style`): `snap` turns the selection into a rounded box (`Kind::Snap`, stroke = two corners), `morph` draws the stroke becoming it (≤ 200 ms, the canvas asks for frames while it runs), `brackets` / `bracket_at` are its corners and grips (`grip_at` -> `Grip`: brackets or corner dots, then the edges (`edge_at`, `resize_edge`); a press inside moves the box unless it lands on read text, Alt makes any press inside move it (`Event::Alt`), arrows nudge it (1 px, Shift 10) and with Ctrl resize from the bottom-right (`Event::Arrow`, `App::nudge`; a focused field takes the arrows first); `keep_inside` keeps it on the screen). Dims and colours come from the active look (`theme::dims`, `theme::accent_of`); select-text mode fills every word box and the picked ones. |
| `ui/kit/motion.rs` | Every widget animation's timing, the new design's (`core/motion.js`): `OPEN` 210 ms, `CLOSE` 150, `MORPH` 190, `GLIDE` 200, `DOCK` 240, `TOAST` 200 (+ 8 px rise), the curves `Out` (expo), `Standard`, `In`, `Ease`; `Shown` = a thing opening/closing by a `Pace` (`WIDGET`, `TOAST_PACE`) from wherever it is; progress by the clock since a motion began; the OS's "show animations" off = instant. `frames()` is the frame clock (a thread, one tick per `FRAME` = 16 ms, never faster: the CPU renderer has no vsync, iced's own frames redrew as fast as a frame could be drawn). Cost rules: a whole window fades by its opacity (`windows::fade`, Windows layered alpha on a thread: nothing redrawn), never a dim or a group of widgets on the CPU; widgets inside the overlay move or scale and redraw only round themselves (the vendored renderer's damage, `frame_times.rs` tests the opening's). |
| `ui/word.rs` | Tap a word: OCR lines around the tap (`recognize_in_child` on a crop, on a thread; no models = no-op), split into words by character share (RTL lines from the right); a second tap on the line makes a range. A press-drag from the highlight or a Shift+click stretches it across lines in reading order (`Picked::extend`; past the lines read, OCR reads a full-width band, `band` / `reread`); one highlight rect per line. Copy copies the text, a line break between lines. |
| `ui/screens/bar/` | The bottom bar (the new design's search bar, solid, on the kit): `view.rs` composes it (`App::bottom_bar`: `kit::grip`, the AI field `kit::field::slots` with its logo and "AI ↵" badge, the `button::compact` pills Search in browser · Copy text · Translate, then the round `kit::icon_button`s from `labs::bar`), the reader's note beside it, its morph into the editing toolbar and the QR chip; `geometry.rs` is its size (pills lose their labels on narrow screens), docking anchors, Tab order and `follow` (while held it eases toward the pointer on the frame clock, ~50 ms, no jump per mouse event; let go, the glide to the nearest anchor starts where it is drawn). Its state is `ui/app/bar.rs`. Nothing is sent after a selection until a pill (or Enter / a key) is chosen, unless `[selection] after = "search"` (Settings > Auto action). |
| `ui/keys.rs` | The one focus rule (#101): a focused text field (bar AI field, Ask panel input) takes every typed letter; the overlay's single-letter shortcuts (`actions::for_key`, E / A on a translation card) only get keys no field captured. `keys::guard(field, f)` wraps a field: Esc while it is focused leaves it and is captured (the global Esc subscription then sends `Message::EscapeTaken`, which never closes; an uncaptured Esc is `Message::Escape` = close), Ctrl+C with nothing selected in it (it wrote nothing to the clipboard) is `Keyed::Copy` = the overlay's copy; Ctrl+S is never a field's. New text field on the overlay: wrap it in `guard`. Tab / Shift+Tab (`overlay::Event::Tab`) walk `bar::stops` (`Opening::bar_focus`; iced buttons have no keyboard focus, so the focus is ours: the field gets the real text-input focus, the rest a soft accent look), Enter / Space press it (`App::activate`); a click resets it. A new bar button: add it to `bar::stops` order and `App::bar_message`. |
| `editor/` | The annotation editor (one component for Edit in place and Snip): `Document` (image or board of captures, items, crop, undo stack; `render` flattens), one file per tool. Tool buttons can hold variants (`ToolInfo::slot`: Arrow > Line, labelled arrow; Text > Label; Step > Pointer; Blur > Redact), shown in a strip under the button. `legend.rs`: the steps' notes in a box (free corner, else a band under the image). `board.rs`: several captures as one image (stack / side / grid; items move with their capture). `blur.rs`: soft blur brush (sigma >= 0.6 x line height + OS-random noise: not invertible); `lines.rs`: line assist (text lines from glyph edges, no OCR; the stroke holds its line). `style.rs`: presets (keys 1-9) and copy/paste style. `dragout.rs`: OS drag of the flattened PNG (Windows only; temp file deleted with the editor/pin). `select.rs`: any drawing tool moves what is painted under the press (`select::grab`: strokes and outlines within a few px, solid items anywhere; the blur brush paints over its own strokes), the Select tool picks by bounds; the selection's handles resize in every tool; pen and highlighter strokes have no frame or handles (dragged by the stroke). The editor draws nothing in the UI's name: its views are `ui/screens/editor/{toolbar,canvas}.rs` (kit parts only); `input.rs` = what the pointer and keys mean (`Editor::key`, `cursor`), `chrome.rs` = what the canvas draws over the image (crop preview, frame, handles, caret) as plain numbers. Toolbar popovers go to the host as a full-screen floating layer (`toolbar::view_at`); `toolbar::place_popover` is the one placement (under the button, above the toolbar when there is no room, clamped to the screen). The Text button's strip holds the text options (size, font, bold, backdrop: `text::Style` on each text). Outputs the host wires: `AddCapture` (then `Editor::append`), `CopyWithText` (`actions::copy::with_text`). |
| `ui/screens/editor/` | `mod.rs` (`Editing`), `toolbar.rs`, `canvas.rs`, `picker.rs`. Edit in place: the editor (`crate::editor`) over the selection at its own pixels (zoom 1/scale), its toolbar where the bar was; Back keeps the edits (shown flattened) and later actions get the edited image. Also the fitted editor for a scrolling capture, and Add capture (board): `Editing::update` hides the editor for a full-screen area picker over the frozen frame; the host crops the picked area (`take_picked`) and `add` puts it on the board, refit to the screen. |
| `ui/quick.rs` | Quick actions: id → what runs (registry action, copy_text, ai_explain), target → area (full_screen, circle, last_region per monitor; `window` is snip-only and counts as circle elsewhere). |
| `ui/screens/translate/` | Translate in place (`mod.rs` = the session and its work; `view.rs` = the language pill and the result card from kit parts) (Ctrl+Shift+T = full screen; `R` in the bar = the selection): `Session` runs `translate::pipeline::translate_progressively` on a thread with `actions::translate::deps()`: top of the screen first, `Deps::batch` sentences per call (offline: `mt::BATCH`; a cloud model: one call), each part shown as it is ready (`Msg::Partial`, at most every 300 ms, drawn from the original like the whole page), then the whole page (an error leaves the original); one log line per translate with the stage times, Alt = peek, a tap on a block = word card (Explain = one streamed AI call with the block's text + crop; `A` = Ask AI panel with that chat). Missing OCR models: the download card (`screens/model_download.rs`). The prompts (download question, progress, error) are short cards, as tall as their text (`kit::panel_frame::short`), never a full-height slab; only the word card is tall. `translate::render` keeps translations from colliding (`separate`: two redraws whose glyphs overlap each give up half the overlap and are fitted again, or the block stays as it was; `Drawn::ink` = the glyph boxes, for tests). |
| `ui/live_layer.rs` | Live translate (Ctrl+Shift+L, tray item): a monitor-sized, always-on-top window made click-through by `live::prepare_layer`, see-through except the patches (`theme::LAYER_CLEAR`); a below-normal-priority thread (`ocr::gently_here`, also for the helper's work) captures on a fixed beat (`translate.live_interval_ms`, 1.5 s; `pump`: a slow step skips beats, never piles up) and runs `translate::live::Live::step_hiding`, one step at a time; a patch whose text changed is hidden before the re-read. While the session is away (`live::away`: WTS lock / switch / disconnect, display off, Windows) nothing is captured, the layer clears, and it resumes when back. Off = stop flag + window closed. Wayland / no layer: one-shot instead. Also opens the mini-controller (`ui/screens/live/controller.rs`, kit parts only: grip, language picker, Pause, Hide = dot, Stop; draggable, takes clicks, `live::prepare_controller` excludes it from capture on Windows, X11 captures get its spot blanked). |
| `ui/snip.rs` | Snip mode (`opencircle run snip`, tray; default keys Print Screen / Alt+ / Ctrl+ = the circle / window / full_screen target of the three default `snip` quick actions): Region · Window · Full · Scrolling switch + timer (the overlay becomes a countdown pill, hides, then `capture` again). A capture goes to `App::snip_captured`: `snip.after` routes it to Copy (the overlay shrinks to a "Copied" pill with Edit for 4 s, focus back to the user's app) and / or the editor. Several monitors: all are captured at the start; the overlay shows the pointer's, at its own scale, and when the pointer leaves it for another monitor (`Msg::Left`, `Snip::follow`) it moves there with that monitor's frozen frame (not during a drag, the editor or a pill; an area never crosses monitors). `Snip` keeps windows and controls in physical desktop px (`desktop_rect`) and shows those of the monitor in view (`Place`) in its logical px. The overlay is placed in physical px on Windows (`place_window`: iced moves in logical px at the window's current scale). Region mode: `Pick`s = windows (titles, our own left out) + their controls (Windows: UIA of the 4 topmost windows, `capture/uia.rs`, on a thread); `chain(p)` = the controls of the topmost window under `p` containing it, smallest first, then that window, then the screen (equal rects one step); hover outlines `chain[walk]`, the wheel walks it, a click (no drag) captures it. Drags snap (`snap`, logical px) to the same rects; Shift = free. The loupe is its own canvas layer. Recent (`snip.history`, off = folder deleted): `history/recent.rs`, PNGs in the local data dir, newest 20 (`history/song.rs` = recent songs). Scrolling (`capture/scroll.rs`: scroll_capture) runs on a thread while the overlay is a progress pill beside the area. |
| `ui/screens/panel/` | Result panels (Search, Text, Ask AI): `mod.rs` = state and work, `view.rs` = what each card shows, from kit parts only, inside the one result card frame (`kit::panel_frame::card`, the design's `.as-card`: widget surface, radius 18, accent glyph + title + model pill, ×, body, actions 18 px under it; solid, no shadow until glass). `screens::panel::card` adds the × with its tooltip; translate and song use it too. Geometry (`kit::panel_frame`): `place` = 40 % of the screen wide (at least 420 px) on the side away from the selection, at the bottom on narrow or portrait screens, or where the user left it this run; `short` for prompts; `free` = the screen part the card leaves, where the bar, chips, popup and pills go; the inner edge resizes it (a grip shows on hover, double-click resets). The AI chat docks at a side; it pins itself after a follow-up (`chat.stays_open`: or at once) or by its header pin, and the App then keeps it (`app/results.rs` `Resident`, never more than one): drawn on the overlay while open, else in its own floating window (`platform::windows::floating`, out of captures, OS drag then dock); the next capture asks into it with its crop (`Panel::ask_about`); only its pin closes it. Its requests carry the last 20 messages + one provider-written summary of older ones (`ask::WINDOW`, `REFRESH`). The logo opens its drawer (History from `store::chats`, Settings: stays open, provider picker from Settings' list, safety-model warning). |
| `store/` | The app's one database, `opencircle.db` in the local data dir (SQLite compiled in, `rusqlite` bundled): growing records, one table set per feature in a file of its own. `mod.rs` = `open` (WAL, `PRAGMA user_version` migrations from `MIGRATIONS`), the one writer lock, `path` (tests: none unless a test sets one). `chats.rs` = saved AI chats (`chats`, `messages`): text only, never image bytes (`had_image` marker), newest 100, while `chat.keep_history` (off = all rows deleted + VACUUM). The config stays in config.toml. |
| `history/` | What the app remembers on this PC, each opt-in: `search.rs` = the local search history (Labs > Search history, `general.search_history`): what Search in browser and Ask AI without a key handed to the browser (kind, query, URL, a small thumbnail). Recorded only; turning it off deletes it. |
| `ui/screens/overlay/edge.rs` | The screen edge per mode (`Mode` = overlay, live, snip): the active look's design Active Look (`kit::looks`, via `theme::kit_look` from the stored id; the user's own colours = a Glow) drawn by kind: Glow = the soft inset glow (`inset 0 0 22px c1, inset 0 0 54px c2`, radius 14); Horizon = that glow on the top and bottom only, fading out to the left and right ends; Hud = the glow + four 30 px corner brackets 12 px in (2.5 px c1, radius 8, 8 px c2 shadow; static); Bezel = 1.5 px c1 line + 8 px c2 band + 28 px c1 glow, never breathes. No moving colours (owner 2026-10-27). Strips (2 for Horizon, else 4) made once per size and look on the first frame; later frames redraw nothing. The ONE motion: the overlay glow breathes (design `ripplePulse`, 4 s, blurs 22/54 -> 38/85 px) after its opening, as edge-strip redraws every 80 ms from a cached depth map (`Breathe`: off during the opening, paused while another motion runs, off with reduced motion and off Windows; live and snip never). The colour-keyed live layer (Windows) gets a thin solid line in c1 for every look (no partial alpha, kept off the key). Config `animate` / `activation_glow` / `thickness` (glow only) are kept but unused. `paint` = a look's edge on a picture (tests); `mask` blanks the live edge out of captures (X11 shows the layer). Goldens per kind: `tests/fixtures/edge-{default,hud,bezel,horizon}-1080p.png` (`OPENCIRCLE_UPDATE_GOLDEN=1` rewrites them). |
| `music/` | Song search (opt-in, the user's own key): `listen` records 10 s of mono 12 kHz while listening only (`capture_linux.rs`: the default sink's monitor over the PulseAudio protocol, pure Rust, PipeWire too; `capture_windows.rs`: WASAPI loopback / mic via cpal, `Downmix` to mono 12 kHz), `identify` sends the clip as WAV to the service (`audd.rs`: multipart request, JSON parsing, error mapping; a second service = one more file + a `Service` variant), `cover` fetches the PNG cover, `history.rs` (local, off by default). The key is `secrets::by_name` (`song-key-audd`); `key_known` caches whether one is saved (Settings updates it), so the overlay's music button shows only then. `ui/screens/song/` = the "Listening… N s" pill (Cancel) and the result card (the one result card frame, kit parts only). |
| `ui/screens/common/language_picker.rs` | The compact language picker (source → target openers, list with search, recent first; `kit::option_list` rows, a badge for what needs AI), shared by the live controller and the one-shot translate pill; picks last for the session. |
| `ui/widgets.rs` | The shared components (`pill`, `surface`, `text_button`, `icon_button`, `chip`, `wide_chip`, `drag_handle`, `input`, `editor`, `progress`, `bubble`, `scroll`, text styles, `with_tip`). Only place that styles a widget. Floating widgets use `theme::floating()` (the look's bar style can force dark / light glass) and the look's accent; `glass` turns solid or outlined with the bar style. Also `float_chip` (Select text / More), `colour_picker` (colours without stroke widths), and for forms `slider`. Fonts: `FONTS` (registered once in `ui::run`), `ui_font()` = the design's stack (Segoe UI Variable Text, Segoe UI, else bundled Inter; Arabic falls back to Noto Sans Arabic); `LINE` = the line height of text fields (they clip to it). Tests: `shot` (now `kit/testing/shot.rs`, re-exported here): `render`, `redrawn` (frames redrawn by damage, as the window does), `render_with` (hover / press / focus), `out_of_reach`. |
| `ui/kit/` | The one UI kit (0.1.2 plan): `tokens.rs` (radii, spacing, sizes, type `Role`s, `fixed` colours), `themes.rs` (the design's 12 themes as data, `current`/`set`/`resolve`; the setup follows the OS: Sapphire dark, Daylight light), `looks.rs` (the 10 Active Looks + custom), `motion.rs`, `text.rs` (fonts, `ui_font`, `MONO`, `text(Role, s)`), `icon.rs` (`Icon`), and the controls `surface`, `button` (Elevated / Accent / Success / Danger / Quiet), `segmented` (+ `boolean`; both as wide as the settings control column, `inline` / `inline_boolean` as wide as their labels), `field`, `chip` (+ `tag`, `badge`, `pill`, `status`, `dot`, `done`), `divider`, `progress`, `keycap` (+ `empty`), `shortcut_field` (`size::CONTROL_COLUMN` x 36, one keycap per key, Rest / Recording / Conflict), `dropdown` (kit-built: an opener and a menu of `option_list` rows in `scroll`; no iced pick list), `slider`, `colour` (`swatch` + `picker`), `field::input` (`.oc-input`), `header` (`regular` 40 px with caption buttons, `compact`), `sidebar` (168 px, one gliding highlight), `setting_row` (`row` / `block`; every row's control sits in one column, `size::CONTROL_COLUMN` wide at the right, rows at least `size::ROW_MIN` tall: the settings layout test checks every page), `card` (info, `theme_card`, `look_card`, `grid`), `scroll` (the one scroll area and scrollbar; `across` for code blocks). `testing/`: `shot`, `golden::check` (golden images, `OPENCIRCLE_UPDATE_GOLDEN=1`), `gallery` (one sheet per control). Depends only on iced, std and itself; `ui/arch_tests.rs` enforces it and the screens' no-styling ratchet (`LEGACY`, only shrinks). |
| `ui/theme.rs` | The only place colours live (Light/Dark palettes, accent, dims). `apply(Theme)` = the Settings choice, `set_os(Mode)` = what the OS reports; System follows the OS. Active looks: `colours(ColourSet)` = each preset palette's edge colours and accent (the one colour table), `along` = a colour round the edge, `accent()` / `dims` / `bracket` / `floating` = what the active look sets. `sapphire` = the new design's token sets (Sapphire for a dark OS, Daylight for a light one, `set_light`; solid look): `t()` = the set in use, fields under the design's names, used by the setup and, with N-18, every screen. |
| `net.rs` | The ONE ureq agent builder: `net::agent(Policy)` with a named policy per caller (`AI`, `MODELS`, `UPDATE`, `SONG`, `COVER`); a test pins each caller's timeouts and another forbids building agents anywhere else. |

| `log.rs`, `diagnostics.rs` | `log!` = `eprintln!` plus the rotating file `<data_local>/OpenCircle/logs/opencircle.log` (1 MB x 3; `OPENCIRCLE_LOG_MAX_BYTES` shrinks it for tests); every line passes `log::redact` (keys, `Bearer`, `key=`, JWTs, home folder -> `~`). | `ui/platform/tray.rs` | Tray icon and its menu's entries (`entries`, one list: Circle to Search, Translate screen, Labs rows only when on, Settings…, Quit; `Entry::trigger` = what each runs, `Entry::shortcut` = its hint). "Shown" = `Shell_NotifyIconGetRect` succeeds: S_FALSE (icon in the overflow flyout) counts, unlike tray-icon's `rect()`. |
| `ui/windows.rs` | The normal windows beside the overlay: Settings and first-run Onboarding (one of each, a second request focuses it), their close handling, the OS-theme feed, and `apply(cfg)` after a save. Also the pinned images (editor Pin / `Ctrl+P`): any number of borderless always-on-top windows, each owning its image (drag, scroll = zoom, hover bar Drag (Windows) / Copy / Save / Close, `Esc` or double-click closes), and the Settings side effects (folder picker, project link). ## Data flow

1. **Trigger**: shortcut, tray or `opencircle capture` sends `Trigger::Capture` or `Trigger::Quick` into one channel.
2. **Capture**: `capture::active_monitor()` (snip: `every_monitor()`) returns a `Frame` (RGBA, size, origin, scale).
   It runs on its own thread (a Wayland portal can wait minutes for the user's OK);
   `Message::Captured` then shows the pre-created window.
3. **Overlay**: the RGBA bytes become the `image::Handle` drawn full-screen. The same
   bytes are later cropped by actions (shared, never copied whole).
4. **Selection**: the canvas reports press/move/release (screen px; the App maps them
   to image px through `overlay::View`); on release `overlay::settle` decides: a zig-zag
   (3+ sharp corners) = a scribble (the box of its padded convex hull, which is also the
   clear area), a mostly straight drag = the rectangle it spans, anything else = the
   loop's bounding box, a tap = the word there (`ui/word.rs`). A new press starts over
   (redraw); a press on a corner handle resizes, on highlighted words a drag stretches
   them across lines (Shift+click too), elsewhere inside moves; Shift adds a selection (Ask AI / Text get every
   crop stacked in one image, the rest the box around all). The ask bar at the bottom
   opens Ask AI with its text (in "wait" mode, Enter with nothing typed = Search). Its
   buttons: Include screen, Copy, Save, Translate, Live, Music, Edit (no Search / Ask AI
   / Text buttons; their keys L / A / T stay). Text selection needs the screen's text.
   Who reads it is `ocr::route` (`App::system_text`, decided per opening in `App::text_by`):
   on Windows, Windows OCR (`ocr::system`) reads the whole screen from the capture on
   (`App::open` -> `read_more` -> `read_band` of the whole screen, a below-normal thread),
   first as it is (selectable ~0.14 s after the first frame), then under 150 % doubled,
   which replaces it (`system::passes`); a failed read (no recognizer, an RTL language)
   falls back to the helper for that opening. The engine is freed after 60 s unused. Otherwise (Linux, `pp_ocr`, Arabic) the helper reads on demand, never at
   open (#123; `word::Screen`, `App::read_more`): nothing is
   read while the opening animation runs; after it the held helper starts (`App::warm`).
   A press, tap, Shift+click or Ctrl+A reads the full-width band under it first (at
   once, `ocr::recognize_band` with only the band's new rows); once text was used (off
   Windows: once the helper is warm, `Message::Warmed`, so the I-beam shows over text
   before any press), the rest follows band by band, nearest the pointer first, gently (the helper on at most
   two cores, below normal priority: `ocr/worker.rs` `Gentle`). One band at a time. A
   drag that began on text before its band arrived becomes a text selection then; one
   let go before it is held (with the keys after it, e.g. Ctrl+C) until it arrives
   (`App::held`). Without the OCR models a note over the bar (`App::reader_note`, state
   `Reader`) offers their download, one click.
5. **Action**: a bar button, Enter (the first action) or the action's key sends
   `Message::Run(&Action)`. `App::run` crops the selection in physical pixels, then:
   `Run::Finish(f)` closes the overlay (so dialogs aren't under it) and calls `f(crop)`
   on a thread (`App::confirm_after`: encoding, clipboard, file; its pill comes back as
   `Message::Confirm`). Clipboard writes and link launches never run on the UI thread;
   `Run::Panel(kind)` opens that result panel over the frozen frame (the bar hides,
   the selection stays). Slow work (PNG, browser launch, keyring, HTTP stream, model
   download, OCR) runs on a thread via `background`; results come back as
   `Message::Panel(id, panel::Msg)` and stale ids are ignored. Dropping a panel
   aborts its task, which disconnects the thread (an AI stream then stops).
6. **Close**: Esc (any focus) or a finishing action: `close()` takes the whole per-capture
   state (`ui/app/opening.rs`: add new per-capture fields THERE, never to `App`): the panel and the
   frame go, and `Opening::finish` releases Lens pages (deleted at once, or once 10 s old so the browser
   has read them); the window shrinks, then hides (`Hiding`). `App::o` is `None` while closed
   (`opening::Open`); `update` drops every message that needs an opening then (`update::works_closed`:
   a new message that must work with no overlay open goes in that list). A press outside the
   panel starts a new selection and drops the panel.

## Change recipes

**Hide or show an unfinished feature (Labs):** `src/labs.rs` is the one place: a `Feature`, its `[labs]` switch
(`Labs`, parsed in `config/parse.rs`, all off by default), and the data the rest reads: `action_feature` (which action id
belongs to it: shortcuts in `hotkey::plan`, `opencircle run`, `actions::for_key`), `bar()` (the bottom bar's buttons),
`tray::entries`, `settings::pages::PAGES` (`lab`) / `slots`. Never an `if` on a feature elsewhere: add it to that data. A hidden
feature keeps its settings in the file. Schema changes: bump `config::VERSION`; a step that changes a value goes in
`Config::parse` (it knows the file's version, e.g. schema 3 sets `selection.after` to "wait"),
and `config::migrate` copies the old file to `config.toml.bak-v<old>` and rewrites it.

**Keep a new kind of record** (search history, an index...): a file in `src/store/` with its functions
(blocking: call them on a thread), and ONE new entry at the END of `store::MIGRATIONS` (its tables; never
edit a shipped entry). Never put image bytes or secrets in it; tests point `store::test_path` at a temp file.

**Add an action** that finishes at once (like Copy):
1. Create `src/actions/<name>.rs` with `pub const ACTION: Action = Action { id, label,
   tip, key, icon, run: Run::Finish(run) }` and its `fn run(crop: Crop) -> Result<(), String>`
   (copy `copy.rs`; keep blocking work off the UI thread, see `save.rs`). Keys:
   DESIGN.md "Shortcuts".
2. Add `mod <name>;` and `<name>::ACTION` to `ACTIONS` in `actions/mod.rs`, in
   action-bar order. The first entry is the Enter default.
3. Icon: the subset font has search, sparkles, type, languages, pencil, copy,
   download, arrow-up, square, x (codes in `assets/lucide/subset.sh`). For another
   glyph, add its code to `subset.sh`, run it, commit the `.ttf`.
4. `cargo test`: the registry tests check ids, labels, tips and keys are unique and
   that the icon is in the font.

**Add an action that stays on screen** (a result panel, like Text):
1. As above, with `run: Run::Panel(Panel::<Kind>)`; add `<Kind>` to `actions::Panel`.
   The action file holds the work (blocking functions, pure logic + its tests).
2. In `ui/screens/panel/`: a `State` variant, its start in `Panel::open` (slow work via
   `background`, keep the abort handle in `work` if it should stop with the panel),
   its `Msg`s in `Panel::update`, its body in `view.rs` (kit parts only). Messages the App must act on
   (close, open another panel) are matched first in `App::on_panel`.

**Add a shared widget**: add a function to `ui/widgets.rs` that builds it from
iced primitives and styles it only with `theme.rs` tokens (add tokens there for
both palettes). Screens call the function; they never set a style themselves.
A screen in the new design takes its controls from the kit (`ui/kit/`: one file per
control, styled only from `kit::tokens` / `kit::themes`, no config or clock, motion as an
`f32` progress). A new kit
control lands with its first user and gets a gallery sheet in `kit/testing/gallery.rs`
(states as rows, Latin + Arabic, Sapphire + Daylight; `tests/fixtures/kit/`,
`arch_tests::every_kit_component_has_a_gallery_sheet`).
A screen file that stops styling in place leaves `arch_tests::LEGACY` (the test says so).

**Add a Settings page**: one `Page` entry in `ui/screens/settings/pages/mod.rs` `PAGES`
(its `Section`, title, optional note / sidebar badge / Labs feature) and one view file
beside it that composes kit parts (`setting_row`, `segmented`, `card`, …); a golden in
`the_ported_pages_match_their_golden_images` (Sapphire + Daylight).

**Add a feature preview** (the hero at the top of a feature's Settings page, only for a
feature that ships; owner 2026-10-27/28): one `Hero` entry in
`ui/screens/settings/previews/mod.rs` `HEROES` (its page, `hidden_previews` key, title, line,
optional Labs feature, shortcut, clip name), the clip's name in `build.rs` `CLIPS`, and the
owner's clip at `assets/previews/<clip>.webp` (spec: docs/previews.md; missing = the
placeholder). `previews::player` decodes it frame by frame while it plays, once per page
visit (`State::players`, `State::played`: the clock runs only meanwhile), then rests on the
last frame with its decoder dropped (reduced motion: the first frame). Tests play
`tests/fixtures/previews/tiny.webp` (`State::play_clip`).

**Animate a widget**: keep its motion in `ui::kit::motion` terms: a `Shown` (open/close by
`WIDGET` or `TOAST_PACE`) or the time it began plus a token (`OPEN`, `CLOSE`, `MORPH`,
`GLIDE`, `DOCK`, `TOAST`) and a `Curve`, set on the first `Message::Frame` that sees it;
never another duration (reduced motion is handled there). Add it to `App::animating`
so the frame clock (`motion::frames`) ticks while it runs. A whole window (popup,
overlay) fades with `windows::appear` / `windows::close` / `windows::fade` (its
opacity, on Windows); inside the overlay a widget only moves or scales (no alpha
for a group of widgets on the CPU renderer). Over the frozen frame only the moving
widget may redraw: keep the overlay canvas's inputs (`overlay::Shown`) unchanged,
and check with `frame_times::frames` (its damage) and `animation_frame_times`.

**Change who reads the screen's text** (main mode): `ocr::route` is the one decision
(setting `selection.text_reader`, Windows OCR's language from `ocr::system::known`), with
its table test `main_mode_text_is_routed_to_the_right_reader`. An engine returns
`Vec<ocr::TextBlock>` (lines, frame px) and `ui/word.rs` (`lines`, `measure`) makes them
selectable, whoever read them; Windows' words become lines in `ocr::system::blocks`.
Selections and one-shot translate call PP-OCR directly (`recognize_in_child`); live mode follows
`ocr::route` too when Windows OCR reads its source language (`ui/live_layer.rs` `Reader`, #56).
Settings > Look & behaviour > Text reader (Windows only) sets the setting; its note about a missing
Windows recognizer comes from `ocr::system::missing` (installed list x display language + translate
source) and its button opens ms-settings:regionlanguage (nothing is installed by us).

**Add a colour**: add it to both `DARK` and `LIGHT` in `theme.rs` (or a `const`
if it is theme-independent). Nowhere else.

**Add an active look** (a preset): a `LookTheme` variant and its row in
`config::PRESETS` (a new colour set: a `ColourSet` variant and its colours in
`theme::colours`), then its tile in `ui/screens/settings/state.rs` `LOOKS`. The tests check
every preset round-trips and draws no key colour on the live layer.

## Test hooks (not for users)

- `OPENCIRCLE_TEST_FRAME=<8-bit RGBA PNG>`: capture returns this image instead of the screen.
- `OPENCIRCLE_TEST_SCROLL=<tall PNG>`: a scrolling snip reads this page (100 px per wheel notch)
  instead of scrolling the screen. With the editor open, its Esc (Back) takes the test shot.
- `OPENCIRCLE_TEST_LIVE_SHOT=<out.png>`: live translate saves its layer once the first patches (or the first error) are drawn.
- `OPENCIRCLE_TEST_UPDATE_URL=<release JSON URL>`: the update check asks this URL (http allowed: a local fake
  release server) 3 s after start, also from a 0.0.0 build. Downloads still need a signature by `RELEASE_PUBLIC_KEY`.
- `OPENCIRCLE_TEST_SHOT=<out.png>`: Esc saves what the overlay shows before closing
  (shot ~150 ms after Esc, with no message in between: a relayout would drop the
  text editor's drawn text from the shot).
